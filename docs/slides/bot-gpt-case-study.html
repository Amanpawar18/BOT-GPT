Auth + Data Model

POST /auth/register { email, password } ├── bcrypt.hash(password, 10) ├── INSERT INTO users (409 if email taken) └── jwt.sign({ sub: userId }) ──► { access_token } POST /auth/login { email, password } ├── bcrypt.compare → 401 if wrong └── jwt.sign(...) ──► { access_token } Every route: Authorization: Bearer <token> └── JwtAuthGuard → req.user = { id, email } 401 if missing / expired / tampered

Schema (key tables):

users (id, email, password_hash) conversations (id, user_id, title, mode, context_strategy, token_count) messages (id, conversation_id, role, content, token_count, sources JSONB) documents (id, user_id, filename, r2_url, status) conversation_documents (conversation_id, document_id, attached_at) ← join table doc_embeddings (id, content, vector(768), metadata JSONB)
Documents are not tied to a conversation — they belong to the user's library and get attached/detached as needed.

LLM Streaming via SSE

POST /conversations/:id/messages { content } │ ├── getDailyTokensUsed(userId) │ 429 JSON if ≥ 100 000 tokens/day │ (before SSE headers — still JSON-switchable) │ ├── buildContextWindow(messages, budget) │ budget = 8 000 (open) | 6 000 (RAG) │ ├── res.setHeader('Content-Type', 'text/event-stream') │ ├── for await (token of llm.stream(...)) │ res.write(`data: {"token":"…"}\n\n`) │ └── res.write(`data: {"done":true, "userTokens":12, "assistantTokens":87, "sources":[{documentId, filename}]}\n\n`) res.end()
RAG is an AI technique that augments LLMs with external knowledge.

Why 429 before SSE?

Once text/event-stream is written, the response is locked — can't switch to JSON error. Daily limit checked first.

Sources on done event

RAG source citations returned in the done event and persisted as JSONB on the message. Frontend renders filename badges.

Context Strategies

Sliding Window (default)

budget = 8 000 t (open) | 6 000 t (RAG) walk newest → oldest: msg₅ 80 t total=80 ✓ msg₄ 120 t total=200 ✓ msg₃ 7400 t total=7600 ✓ msg₂ 900 t total=8500 ✗ stop window = [msg₃, msg₄, msg₅] chronological Edge: msg₅ alone > budget? → include it anyway (min-1 guarantee)

Zero extra API calls

Guaranteed most-recent context. Old turns silently dropped when history overruns budget.

Summarization

Step 1 first-pass window older = messages before window Step 2 summarize older slice (1 LLM call) summary = llm.invoke(older) summaryTokens = estimateTokens(summary) Step 3 rebuild window recent = buildWindow(budget - summaryTokens) ← total never overruns budget Step 4 send to Gemini: [ SystemMessage, AssistantMessage("[Summary]: …"), …recent…, HumanMessage ]

Trade-off

1 extra LLM call per request when history is long, but preserves semantic content of old turns (80-90% token reduction).

RAG Pipeline

Ingest path

POST /documents { PDF }
↓ Upload → Cloudflare R2 (S3-compat, free egress)
↓ RecursiveCharacterTextSplitter
chunkSize:1000 · overlap:200
↓ GoogleGenerativeAIEmbeddings → VECTOR(768)
↓ PGVectorStore · metadata: { document_id, filename }
POST /conversations/:id/documents/:docId
↓ INSERT conversation_documents

Query path

POST /conversations/:id/messages
↓ getAttachedDocuments(convId) → [docId…]
↓ Parallel similaritySearch per document_id
perDoc = ceil(topK / docs.length)
↓ "Context:\nchunk1\n---\n…\nAnswer: {q}"
↓ withRetry(() → llm.stream(messages))
↓ done event → sources persisted as JSONB
Filter by document_id (not conversation) — documents can be shared across conversations with no vector duplication.

Document Library

Documents belong to the user library, not a conversation. Conversations attach/detach documents as needed.

POST /documents upload to library GET /documents list user library DELETE /documents/:id delete + R2 object + vectors GET /conversations/:id/documents list attached POST /conversations/:id/documents/:docId attach 409 if already attached DELETE /conversations/:id/documents/:docId detach

Why library model?

A document uploaded once can be attached to multiple conversations without re-uploading or re-embedding. Detach removes the join row only — embeddings stay.

Cloudflare R2

S3-compatible, zero egress fees. DeleteObjectCommand called on document delete — no orphaned objects.

Reliability & Cost Controls

Token Limits

getDailyTokensUsed: SUM(msg.token_count) JOIN conversations WHERE user_id = ? AND created_at ≥ UTC day if used ≥ 100 000: res.status(429).json(...) ← before SSE headers After stream: saveMessage(..., userTokens) saveMessage(..., assistantTokens) token_count += total

UTC midnight reset

startOfDay.setUTCHours(0,0,0,0) — consistent across timezones. Configurable via DAILY_TOKEN_LIMIT env.

LLM Retry

withRetry(fn, maxAttempts=3): delay = 1000ms attempt 1 → fail → sleep 1s attempt 2 → fail → sleep 2s attempt 3 → OK → stream all 3 fail → throw → SSE: {"error":"LLM unavailable"} → toast notification on client Applied to: streamOpenChat() streamRagChat()

Tested with Jest

Mock setTimeout to instant. Fail twice then succeed. Assert 3 calls, correct tokens returned.

Caching

GET /conversations?page&limit key = `convlist:${userId}:${page}:${limit}` cache.get(key) → hit: return → miss: query DB cache.set(key, ttl=60s) Invalidation: create() → cache.del(`convlist:${userId}`) remove() → cache.del(`convlist:${userId}`)

In-memory now / Redis later

Zero infra for single instance. Swap to Redis store when scaling — zero service code changes.

Docker + CI

Multi-Stage Dockerfile

# Stage 1: deps — layer-cached
FROM node:20-alpine AS deps
COPY package*.json ./ && RUN npm ci

# Stage 2: builder
FROM node:20-alpine AS builder
COPY --from=deps /app/node_modules .
COPY . . && RUN npm run build

# Stage 3: runner — minimal image
FROM node:20-alpine AS runner
ENV NODE_ENV=production
RUN adduser --system --uid 1001 nestjs
COPY --from=builder /app/dist ./dist
COPY --from=deps /app/node_modules .
USER nestjs          # non-root
EXPOSE 3001
CMD ["node", "dist/main"]

Non-root user

uid 1001 cannot write to system dirs if the container is compromised.
